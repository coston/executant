# Review: src/tests/forEach.test.ts

The recent changes migrate reducer assertions from a flat `iteration: {current, total, item}` shape to an `iterationHistory: IterationRecord[]` array, correctly reflecting the new design where each `step:iteration` event appends a new `"running"` record while marking the previous one `"complete"` — all assertions in the migrated tests are logically consistent with this model and no bugs are apparent. The new `"runWorkflow — forEach log step substitution"` describe block and the nested-steps runner/reducer suites are well-structured, and the edge cases covered (empty list, shell-command failure, `continue_on_error` propagation at both child and outer levels) are solid. Three gaps stand out: (1) there is no runner-level test for `repeat` combined with nested `steps:` — only `loadWorkflow` exercises that path; (2) the `continueOnError propagates to ForEachTask` load test (line 97–109) only verifies the flag is parsed, not that the runner actually swallows the error at execution time for a single-command forEach; and (3) there is no reducer guard test for `step:inner` arriving before any `step:iteration` (i.e., no running record exists), which is an edge case the reducer could silently mishandle.
